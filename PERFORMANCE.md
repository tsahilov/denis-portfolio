# Оптимизация портфолио Дениса Афанасьева

Дата: 5 ноября 2026. База: main, a062cc4b9af663a8e1bdc25b297e6f679f16a0fc. Ветка: perf/lazy-media.

## Что проверено

Опубликованная страница https://denisafanasjev.ru/ совпала с index.html текущего main после нормализации переводов строк. Это подтверждает актуальность HTML, но не является побайтовой проверкой всех опубликованных медиа. В ходе работы main оставался на том же коммите. GitHub Pages использует домен из CNAME. В main изменения не вносились, развёртывание не запускалось.

Основная нагрузка: 15 MP4 суммарно 202,42 МБ, много крупных WebP, все изображения загружались сразу. Все видео содержали autoplay; Chrome в тесте самостоятельно приостанавливал дальние ролики, но запросы к ним всё равно выполнялись. Поэтому дополнительную экономию декодирования нельзя выдавать за измеренный выигрыш CPU/GPU.

В исходной странице не было размеров изображений. Шрифт Inter 352 240 байт на медленной сети приходил поздно. У b2b-30.mp4 атом moov расположен после mdat; у остальных 14 роликов — перед ним.

## Сделанные итерации

1. Размеры width/height из реальных файлов для всех активных изображений; decoding=async; loading=lazy ниже первого экрана. Аватар и первая обложка остаются обычными ранними изображениями. Для мобильного source genai-80 указаны собственные размеры. Пути к шрифтам стали относительными, чтобы работали и на домене, и в подпапке GitHub Pages.
2. Отдельный media.js с defer. MP4 не получают активный URL до появления в видимости. IntersectionObserver учитывает пересечение с экраном и обрезку горизонтальным скроллом. Постеры появляются в пределах 300 px от экрана; все 15 постеров — новые производные WebP, вместе 654 КБ. Оригинальные изображения и видео не изменены.
3. В видимости запускается muted/loop/playsinline; вне экрана и при скрытии страницы — pause. При reduced-motion и Save-Data видео остаются с ручным управлением, без автоматического воспроизведения. preload=none и прямое присвоение video.src позволяют показать рабочие встроенные кнопки без запроса MP4 до нажатия. При отказе autoplay остаются controls; без IntersectionObserver доступны ручные проигрыватели; без JavaScript — 15 прямых ссылок на MP4.
4. Удалены повторные правила опыта и мобильных сеток, сокращены пустые строки CSS. Порядок оставшихся правил и композиции сохранены. Текущий IDS не заменялся новой системой стилей.
5. Добавлена копия InterVariable-portfolio.woff2: 113 540 байт вместо 352 240 (−67,8%). Сохранены переменные начертания и возможности OpenType для включённых символов. Поддерживаются базовая латиница, русский алфавит и основные знаки; оригинальный полный шрифт сохранён. Для новых языков с дополнительными символами нужно пересобрать subset или вернуть полный шрифт. Добавлен запасной Arial с согласованными метриками. Единственный preload — основной шрифт; массового preload изображений/видео нет.

## Измерения до и после

Chrome headless на этом компьютере; холодный контекст на каждый запуск, размер экрана 390×844 или 1440×844, DPR 1. Статический локальный сервер без сжатия/кэширования CDN. Это лабораторное сравнение, не Lighthouse и не статистика реальных посетителей.

Быстрый локальный тест: снимок через 2,5 секунды после события load. CDP Network.dataReceived учитывает полученные данные ответов, включая незавершённые загрузки; это не точный объём байтов на сетевом интерфейсе. Исходный сервер теста не реализует HTTP Range, поэтому абсолютные значения видео нельзя переносить на GitHub Pages. Оба варианта измерены одинаковым способом.

| Показатель | До | После |
|---|---:|---:|
| Данные ответов, mobile | 95.30 МБ | 7.05 МБ |
| Данные ответов, desktop | 95.85 МБ | 5.35 МБ |
| Начатые запросы, mobile | 63 | 19 |
| Запросы MP4 на первом экране | 15 | 0 |

Более строгий мобильный тест: 1,6 Мбит/с загрузка, задержка 150 мс, CPU ×4; по три холодных запуска, окно 12 секунд после DOMContentLoaded. Медианы:

| Показатель | До | После |
|---|---:|---:|
| LCP | 1.160 с | 1.008 с |
| CLS | 0.102610 | 0.000206 |
| Начатые запросы | 62 | 18 |
| Запросы MP4 | 15 | 0 |

В фиксированном 12-секундном окне обе версии почти полностью занимают доступную полосу: получено около 2,4–2,5 МБ. Поэтому для этого теста нельзя заявлять снижение трафика на 90%: улучшились порядок запросов, отсутствие MP4 и стабильность текста. Native lazy loading всё ещё заранее подгружает несколько крупных WebP. Полная загрузка страницы со всеми просмотренными видео остаётся тяжёлой до перекодирования.

Промежуточный быстрый замер только после lazy images: около 22 МБ завершённых ресурсов вместо 54–57 МБ. После видео и шрифта: около 7,0 МБ. Это отдельная метрика PerformanceResourceTiming, исключающая незавершённые ответы; её нельзя смешивать с CDP-данными из таблицы.

## Проверки поведения и дизайна

- Первый экран до/после совпал пиксель в пиксель при 390 и 1440 px, включая subset шрифта.
- На 320, 390, 767, 768, 1024 и 1440 px нет горизонтального переполнения страницы. Все три существующие мобильные карусели сохраняют горизонтальную прокрутку и число элементов.
- Проверены: запуск видимого видео, пауза после прокрутки, обработчик скрытия страницы (симуляция visibilitychange), reduced-motion и ручной запуск, Save-Data, отсутствие IntersectionObserver, ссылки без JavaScript.
- В свежих reduced-motion/Save-Data контекстах и запасном сценарии без IntersectionObserver — 0 запросов MP4 до ручного запуска.
- Ошибок JavaScript и обнаруженных сломанных загруженных изображений нет. Синтаксис media.js и git diff --check проверены.

Ограничения: проверки выполнены в Chrome, без реального iPhone/Android/Safari. GPU, энергопотребление и частота кадров напрямую не профилировались. Pause не гарантирует прекращение уже начатой загрузки/освобождение буфера браузером. Нужен финальный визуальный проход всех кейсов на телефоне до слияния. Постеры взяты из кадра на 0,1 с; можно вручную выбрать более выразительные кадры.

Настройки: MP4/H.264 (libx264), yuv420p, preset slow, CRF 20–23 desktop / 22–25 mobile, faststart; убрать аудиодорожку только у этих беззвучных фоновых циклов. Сохранить исходную частоту кадров, если она не выше 30; перевод 50/60→30 делать только после проверки плавности. Для мелкой типографики начинать с CRF 20–21. Сначала экспортировать 1–2 ролика и сравнить на реальном размере, затем пакет. Цель для коротких циклов — около 1–4 МБ mobile; для 62-секундного квадратного ролика нужен отдельный компромисс качества/веса, этот бюджет не обещается.

Пример для квадратного candinsky, новая копия (FFmpeg):

```sh
ffmpeg -i video/candinsky-20.mp4 -an -vf "scale=1080:1080:force_original_aspect_ratio=decrease:force_divisible_by=2" -c:v libx264 -preset slow -crf 21 -pix_fmt yuv420p -movflags +faststart video/candinsky-20-desktop.mp4
ffmpeg -i video/candinsky-20.mp4 -an -vf "scale=720:720:force_original_aspect_ratio=decrease:force_divisible_by=2" -c:v libx264 -preset slow -crf 23 -pix_fmt yuv420p -movflags +faststart video/candinsky-20-mobile.mp4
```

Для b2b-30 даже перенос moov в начало без перекодирования полезен; нынешний файл имеет moov в конце. У остальных файлов faststart уже есть, повторять remux ради него не нужно:

```sh
ffmpeg -i video/b2b-30.mp4 -c copy -movflags +faststart video/b2b-30-faststart.mp4
```

WebM/AV1 пока не добавлены: сначала получить качественные лёгкие H.264-копии с широкой совместимостью. Подключение адаптивных видео и srcset запланировано после появления реальных файлов; ссылки на отсутствующие варианты не добавлялись.

## Следующий этап: изображения

Первыми подготовить мобильные копии genai-15 (3,32 МБ), domclick-30 (3,02), domclick-20 (2,60), genai-55 (2,42), randevu-10 (2,37), genai-80 и giga-ban-10/40. Для полноэкранных мобильных изображений — WebP шириной 768 и 1152 px, quality 82–88; для мелкой типографики 88–92 либо lossless после сравнения. Для desktop — 1440/1920 px только там, где изображение действительно занимает всю ширину; карточки экспортировать по максимальной ширине карточки × DPR. Не увеличивать маленькие исходники. Для неодинаковой композиции (существующий genai-80-mobile) сохранять picture с отдельным мобильным кадром, а не заменять его общим srcset.

Практический ориентир: 100–300 КБ на полноширинную мобильную карточку; сложный коллаж может требовать больше. Каруселям нужны реальные пропорции и собственные sizes, особенно Domclick KV с разной шириной карточек. Не применять одно sizes ко всем сеткам. Неиспользуемые изображения не участвуют в загрузке и не являются первым приоритетом.

## Повторение измерений и откат

Нужны Node.js, Chrome и Playwright. Установить инструмент локально: npm install --no-save --package-lock=false playwright. Сайт по-прежнему работает без сборки и без Node.js на хостинге.

```sh
node tools/performance-audit.cjs current --checks
node tools/performance-audit.cjs slow-before --slow --baseline
node tools/performance-audit.cjs slow-after --slow
```

Результаты сохраняются в .performance-results/ (игнорируется Git). Порт локального сервера 8765 должен быть свободен. CHROME_PATH и PLAYWRIGHT_MODULE позволяют выбрать установленный браузер/библиотеку. --baseline читает исходные HTML/CSS из a062cc4 через Git; после shallow clone без этой истории сначала нужно получить базовый коммит. Для пересборки шрифта: pip install fonttools brotli, затем python tools/subset-font.py.

Изменения разделены на коммиты: изображения, видео, очистка CSS, шрифт, исправление ручного запуска и отчёт. До слияния достаточно закрыть PR для отмены. После слияния — GitHub Revert всего PR либо git revert соответствующих коммитов в обратном порядке. Простое удаление media.js не является корректным откатом, поскольку video использует отложенные URL.

После ручных экспортов: подключить варианты через picture/srcset и выбор видео до инициализации; повторить этот же тест, затем проверить Safari/iPhone и Android, все карусели и видео. Публиковать main только после визуального просмотра и проверки PR.
