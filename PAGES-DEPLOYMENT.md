# Публикация GitHub Pages

Сейчас Pages забирает весь корень ветки. В нём 594 693 619 байт отслеживаемых Git файлов (594,69 МБ); архив неудачного запуска #20, по журналу GitHub, весил 583 МБ. Исходные MP4 занимают 259,70 МБ, оптимизированные MP4 — 258,35 МБ. Исходные WebP — 61,26 МБ; дополнительно публиковались отчёты и инструменты.

`node tools/build-pages.cjs` собирает `.pages-dist` только из `index.html`, `style.css`, `media.js`, `CNAME`, используемых шрифтов и всех локальных медиа, найденных в HTML/CSS/JS. Скан охватывает `src`, `srcset`, `data-src`, `data-variants`, постеры и ссылки внутри `noscript`. Отсутствующий файл или ссылка на исходный MP4 останавливают сборку. Пустой `.nojekyll` отключает обработку Jekyll. `CNAME` сохраняет `denisafanasjev.ru`.

После изменения резервных ссылок без JavaScript на версии 768 px локальный набор: **275 198 957 байт (275,20 МБ), 212 файлов**, на **53,7% меньше** отслеживаемого содержимого корня. Объём архива Actions может немного отличаться из-за упаковки и метаданных. Исходные медиа продолжают храниться в Git.

Workflow `.github/workflows/pages.yml` собирает и загружает ровно `.pages-dist`; при pull request проверяет артефакт, при push в `main` развёртывает его. После проверки PR и до объединения в настройках репозитория **Settings → Pages → Build and deployment → Source** нужно выбрать **GitHub Actions**. Пока источник остаётся `Deploy from a branch`, Pages будет продолжать собирать весь корень ветки, даже если workflow уже существует. Прямое развёртывание из PR отключено. Неудачный запуск #20 таким образом не исправится задним числом; следующий запуск после объединения и переключения источника должен публиковать компактный артефакт.
